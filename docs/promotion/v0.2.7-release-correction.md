# v0.2.7 Release Correction

This audit records the preparation of the immutable `npa-mathlib` `v0.2.7`
snapshot after the `v0.2.6` release checksum sidecar was found to contain a
machine-local absolute archive path.

## Scope

| Field | Value |
| --- | --- |
| Previous immutable snapshot | `npa-mathlib` `v0.2.6` |
| Current snapshot | `npa-mathlib` `v0.2.7` |
| Catalog change | none; all public module and declaration identities are retained |
| Proof change | none; source and canonical certificate bytes are retained |
| Corrective change | release checksum sidecar records the relative archive filename |
| `proof_evidence` | `false` |

The `v0.2.6` tag and release assets remain immutable. The new snapshot is
published under a new version so that the corrected sidecar can be consumed
without rewriting the historical release.

## Required gates

The current target must pass package check, checked hash validation, checked
certificate build, cache-off source-free reference verification, axiom report,
theorem index, theorem-premise report, export summary, publish-plan,
check-generated, artifact-ledger audit, promotion-origin registry validation,
downstream smoke checks, and `git diff --check`.

The release archive must contain only the intended tracked package tree under
`npa-mathlib-v0.2.7/`. Its SHA-256 sidecar must contain the archive checksum
and the relative filename `npa-mathlib-v0.2.7-release-artifacts.tar.gz`, with
no absolute filesystem locator.

## Attempt and resolution

The initial package gates and artifact-ledger audit passed. The current and
read-only `v0.2.6` baseline promotion-origin registries also validate
successfully. The first reconciliation dry-run exposed the version-only
registry-tooling defect described below; it failed before writing an
attestation or changing `promotion-origins.json`:

```text
cargo +1.95.0 run -q --manifest-path ../npa-core/Cargo.toml -p npa-cli -- \
  package reconcile-promotion-origin-registry \
  --root . \
  --previous-target-root <v0.2.6-baseline-root> \
  --audit docs/promotion/v0.2.7-release-correction.md \
  --out docs/promotion/v0.2.7-release-correction.json \
  --dry-run --json
```

Result:

```text
status=failed
reason_code=promotion_registry_reconciliation_event_invalid
path=$.registry_hash
failure_class=campaign-stop/post-write
```

At that failure boundary, only the pre-existing tracked v0.2.7 package
correction files and this audit were modified; the registry and reconciliation
attestation were unchanged. The registry tooling was then updated to treat a
package-version-only snapshot as a validated no-op. The unchanged source of
the `fixtures/downstream-smoke` passthrough module was also rebuilt with the
current CLI; its certificate and generated pins now match the canonical
rebuild. The other three downstream smoke fixtures were already current.

The final reconciliation dry-run and apply both passed with
`promotion_registry_no_catalog_change`, preserving the registry byte-for-byte
and creating no attestation. Final package, generated-artifact,
artifact-ledger, registry, proposal-transition, downstream-smoke, and diff
gates passed. No registry JSON was hand-edited.

## Final publication result

The aggregate v0.2.7 package correction commit has been pushed, and the
`npa-mathlib` child repository has been synchronized from that aggregate tree.
The release archive and SHA-256 sidecar were generated from the verified child
tree; the sidecar contains only the relative archive filename. The synchronized
child commit, tag, release URL, asset checksums, and downstream publication
status are maintained in the ignored campaign ledger and the final publication
report. Immutable tag and release creation are the remaining publication
actions.
